Worship Scheduler / Architecture 01

Frontend architecture

The browser owns presentation and session state. Next.js App Router composes the workspace, while route handlers provide the application boundary for authentication, scheduling, validation, and future data access.

Rendering model

App Router layouts provide the persistent shell. Interactive login, navigation, dev mode, and session guarding stay in client components.

Auth handoff

The login form posts only the entered name to the server route, receives Supabase tokens, then hydrates the browser client session.

Current boundary

Several workspace endpoints still return mock or in-memory data. The API route boundary is ready to move those reads and writes to Postgres.

Evidence: src/app, src/components/layout, src/components/auth/session-guard.tsx, src/lib/supabase/client.ts, src/app/api.
