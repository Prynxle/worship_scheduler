Worship Scheduler / Architecture 02

Backend architecture

Next.js route handlers are the server boundary. Name authentication uses the Supabase Admin API, while schedule generation and validation remain domain services that can evolve from mock adapters into Postgres-backed workflows.

Auth boundary

The name route validates the active roster case-insensitively, creates or recovers a hidden Supabase Auth identity, and returns a session.

Scheduling boundary

The engine, validator, fairness, cooldown, leader rotation, and replacement modules keep business rules separate from HTTP transport.

Data maturity

Core tables and RLS migrations exist. Several API routes still use mock data, so persistence is the next backend integration seam.

Evidence: src/app/api, src/lib/scheduling, src/lib/supabase/client.ts, supabase/migrations, AGENTS.md scheduling rules.
